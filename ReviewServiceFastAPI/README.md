

## What it does

Manages reviews left by users for hotel stays: create, read, update, soft-delete,
and filter by user / hotel / booking.

## Architecture

```
routers/review_router.py     → HTTP layer (FastAPI route handlers, request/response shaping)
services/review_service.py   → Business logic (rating validation, orchestration)
repositories/review_repository.py → Data access (SQLAlchemy queries, soft-delete filtering)
models.py                    → SQLAlchemy ORM model (the `reviews` table)
schemas.py                   → Pydantic request/response DTOs
exceptions.py                → Domain exceptions (ReviewNotFoundError, InvalidRatingError)
main.py                      → App wiring, global exception handlers, startup
```

This mirrors the original Go service's `controllers → services → db/repositories → models`
split. FastAPI's route handlers absorb what the Go `controllers/review.go`
did (request parsing, response formatting), since Pydantic already validates
the request body before the handler runs — there's no separate middleware
layer needed for that step the way `middlewares/validator.go` provided in Go.

## Endpoints

| Method | Path | Description | Go equivalent |
|---|---|---|---|
| POST | `/reviews` | Create a review | `CreateReview` |
| GET | `/reviews` | List all reviews | `GetAllReviews` |
| GET | `/reviews/{id}` | Get one review by ID | `GetReviewById` |
| PUT | `/reviews/{id}` | Update a review's comment/rating | `UpdateReview` |
| DELETE | `/reviews/{id}` | Soft-delete a review | `DeleteReview` |
| GET | `/reviews/user?user_id=` | List reviews by user | `GetReviewsByUserId` |
| GET | `/reviews/hotel?hotel_id=` | List reviews by hotel | `GetReviewsByHotelId` |
| GET | `/reviews/booking?booking_id=` | List reviews by booking | `GetReviewsByBookingId` |
| GET | `/ping` | Health check | `PingHandler` |

All list/get responses are wrapped in the same envelope shape as the Go
service's `utils.WriteJsonSuccessResponse` / `WriteJsonErrorResponse`:

```json
{
  "success": true,
  "message": "Reviews fetched successfully",
  "data": [ ... ]
}
```

## Validation rules 

- `comment`: required, 1–1000 characters
- `rating`: required, integer 1–5 (enforced twice, same as the original —
  once by Pydantic at the request boundary, once again in the service layer)
- `user_id`, `booking_id`, `hotel_id`: required on create

## Data model

Same schema as the Go migration (`db/migrations/20250101000000_create_reviews_table.sql`):

| Column | Type | Notes |
|---|---|---|
| id | BIGINT | primary key |
| user_id | BIGINT | indexed |
| booking_id | BIGINT | indexed |
| hotel_id | BIGINT | indexed |
| comment | TEXT | 1–1000 chars, enforced at the API layer |
| rating | INT | CHECK 1–5 |
| created_at | TIMESTAMP | |
| updated_at | TIMESTAMP | auto-updates |
| deleted_at | TIMESTAMP, nullable | soft-delete marker |
| is_synced | BOOLEAN | carried over from the Go model; not otherwise wired up there either |

Deletes are **soft** — `DELETE /reviews/{id}` sets `deleted_at` rather than
removing the row, and every read filters `deleted_at IS NULL`, exactly like
the original.

## Running it

### 1. Install dependencies

```bash
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Configure environment

```bash
cp .env.example .env
# edit .env with your MySQL credentials
```

### 3. Set up the database

The app auto-creates the `reviews` table on startup for local development.
If you'd rather manage schema explicitly (e.g. in production), run
`migrations/001_create_reviews_table.sql` against your database directly
and it'll skip re-creating it.

```bash
mysql -u root -p airbnb_reviews < migrations/001_create_reviews_table.sql
```

### 4. Run the server

```bash
uvicorn app.main:app --reload --port 8000
```

Interactive API docs (auto-generated by FastAPI, not present in the Go
version) are available at `http://localhost:8000/docs`.

## Example requests

**Create a review:**
```bash
curl -X POST http://localhost:8000/reviews \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": 1,
    "booking_id": 42,
    "hotel_id": 7,
    "comment": "Great stay, very clean rooms.",
    "rating": 5
  }'
```

**Get reviews for a hotel:**
```bash
curl "http://localhost:8000/reviews/hotel?hotel_id=7"
```

**Update a review:**
```bash
curl -X PUT http://localhost:8000/reviews/1 \
  -H "Content-Type: application/json" \
  -d '{"comment": "Updated: still great, even better on a second visit.", "rating": 5}'
```

**Delete a review:**
```bash
curl -X DELETE http://localhost:8000/reviews/1
```
